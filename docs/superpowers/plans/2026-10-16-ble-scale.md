# ble-scale Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Safari + beacio web app that shows the net weight of a CK829 scale with a 5-slot MRU tare stack.

**Architecture:** Static files served from the repo root by GitHub Pages. Pure logic modules (`decoder`, `measurement`, `tares`, `storage`) have no DOM access and are tested with `node --test`. `ble.js` wraps the beacio scan API; `app.js` wires DOM, BLE and logic.

**Tech Stack:** HTML, CSS, ES modules, Web Bluetooth scanning (`requestLEScan`), service worker, `localStorage`, Node 22 test runner. No dependencies.

**Spec:** `docs/superpowers/specs/2026-10-16-ble-scale-design.md`

## Global Constraints

- No framework, no build step, no runtime dependencies, no npm packages.
- No GATT connection, no writes, no pairing; scan only.
- UI text German with Swiss spelling ("ss", never "ß"); code, comments, docs English.
- Timings: stale after 6000 ms without a valid frame; wake hint after 20000 ms; steady = ≥3 frames over ≥1500 ms within 1 g, latest frame fresh.
- Tare stack: max 5, positive integer grams, same-tare tolerance ±2 g.
- Never persist the empty reference `Z`; never show a missing packet as `0 g`; never clamp negatives.
- Manifest `"display": "browser"`. Font self-hosted, no runtime Google Fonts.
- Commit messages without any AI attribution.

## Review Focus

- beacio bursts (many frames with one timestamp): steadiness must not pass from one burst alone → test in Task 2.
- Frames from a second scale (other bytes 0-5) during a scan → ignored, test in Task 2.
- Corrupt localStorage JSON → app starts empty, broken value kept under backup key, test in Task 4.
- Saving a tare while a tare is active stores total `G`, not net → test in Task 3 (`saveTare` gets G from caller) and enforced in Task 6 wiring.
- Page hidden then visible → scan stopped, state disconnected, no live weight until reconnect + empty confirm → test in Task 2 (`disconnect`).

### Task 2: Measurement state machine

**Files:** Create `src/measurement.js`, `tests/measurement.test.js`.

**Interfaces:**
- Consumes: `decodeAdvertisement` output `{grams, scaleId, model}` (only grams and scaleId used).
- Produces: `class Measurement` with `constructor(opts = {staleMs: 6000, hintMs: 20000, steadyFrames: 3, steadyMs: 1500, steadyRangeG: 1})` and methods, all taking `now` (ms) explicitly:
  - `connect(now)`: phase `'needEmpty'`, clears raw, samples, zero, scaleId; remembers `connectedAt`.
  - `disconnect()`: phase `'disconnected'`, clears zero and samples.
  - `frame({grams, scaleId}, now) -> boolean` (false = ignored). Ignored when disconnected or when `scaleId` differs from the locked one. First accepted frame locks `scaleId`. A frame in phase `'stale'` moves to `'needEmpty'`.
  - `tick(now)`: in `'needEmpty'`/`'live'` with a last frame older than `staleMs` → `'stale'`; store `staleTotal = raw - zero` if zero was set, else `null`; clear zero.
  - `isSteady(now) -> boolean`.
  - `confirmEmpty(now) -> boolean`: only in `'needEmpty'` and steady; sets `zero = raw`, phase `'live'`.
  - `resetZero()`: from `'live'` to `'needEmpty'`, zero cleared.
  - `view(now) -> { phase, raw, zero, total, staleTotal, ageMs, steady, hint, scaleId }`; `total = raw - zero` only in `'live'`, else `null`; `hint` = true when no frame for `hintMs` (since last frame, or since connect if none).
- Steadiness uses accepted frames within the last 5000 ms: count ≥ steadyFrames, last.t - first.t ≥ steadyMs, max - min ≤ steadyRangeG, and `now - last.t ≤ staleMs`.

- [ ] Step 1: tests:
  - connect + frames 0 g at t=0,500,1000,1500 → `isSteady(1500)` true; `confirmEmpty` → live; `view.total` 0.
  - 30 frames all at t=0 (burst) → not steady.
  - frames 0,0,2 g over 1.5 s → not steady.
  - live with zero=-5 and raw=838 → total 843; negative total stays negative.
  - frame from other scaleId ignored (returns false, raw unchanged).
  - no frame for 6001 ms → stale, `staleTotal` kept, `total` null; next frame → needEmpty, `confirmEmpty` needed again.
  - `disconnect` → frames ignored; `view.phase` 'disconnected'.
  - `confirmEmpty` when not steady → false, phase unchanged.
  - hint false at 19999 ms, true at 20001 ms after connect with no frames.
  - 10 stale/wake cycles each with a different raw offset → total correct each time (no accumulated offset).
- [ ] Step 2: run → fail. Step 3: implement. Step 4: run → pass.
- [ ] Step 5: commit `feat: add measurement state machine`.

### Task 3: Tare stack

**Files:** Create `src/tares.js`, `tests/tares.test.js`.

**Interfaces:**
- Produces pure functions on `TareState = { stack: Array<{id, grams, createdAt, lastUsedAt}>, activeId: string|null }` (timestamps ISO strings, `now` passed as ms):
  - `emptyTares() -> TareState`
  - `saveTare(state, grams, now, makeId = randomId) -> TareState`; throws `RangeError` unless grams is an integer > 0.
  - `selectTare(state, id, now) -> TareState`
  - `selectNone(state) -> TareState`
  - `deleteTare(state, id) -> TareState`
  - `activeGrams(state) -> number` (0 when none)
- Rules from the spec "Tare stack" section; tolerance match picks the closest entry, ties to the lower index.

- [ ] Step 1: tests:
  - `[320,185,740,96,510]` + save 430 → `[430,320,185,740,96]`, 430 active.
  - `[430,320,185,740,96]` select 185 → `[185,430,320,740,96]`, 185 active, its `lastUsedAt` = now, others unchanged.
  - save 321 on `[430,320,...]` → no new entry; entry becomes 321 at top, `createdAt` unchanged.
  - save 323 on `[320]` → new entry (outside ±2).
  - save 312 on `[310, 314]` → ties → 310 entry (lower index) becomes 312.
  - selectNone → activeId null, stack order unchanged.
  - delete active → activeId null; delete other → active unchanged.
  - inputs not mutated (deep-equal before/after).
  - save 0, -5, 1.5 → RangeError.
  - 7 different saves → exactly last 5 kept.
- [ ] Step 2-4: fail, implement, pass.
- [ ] Step 5: commit `feat: add MRU tare stack`.

### Task 6: BLE adapter and app wiring

**Files:** Create `src/ble.js`, `src/app.js`.

**Interfaces:**
- `ble.js`: `scanAvailable() -> boolean`; `startScan(onBytes: (Uint8Array) => void) -> Promise<void>` using `navigator.bluetooth.requestLEScan({acceptAllAdvertisements: true, keepRepeatedDevices: true})`, forwarding a normalized `{id, name, manufacturerData: Map<number, Uint8Array>, serviceData: Map<string, Uint8Array>}` built from the event (DataView → Uint8Array; keep company key 0; `id` = `event.device.id`) (`startScan(onAdvertisement)`); `app.js` calls `decodeAdvertisement`; `stopScan()` stops the scan and removes the listener. Must be called directly from the tap handler (user activation).
- `app.js`: one `Measurement`, settings from `loadSettings(localStorage)`. Frames → `decodeFrame` → `measurement.frame(..., performance.now())`. Render throttled with `requestAnimationFrame`; a 250 ms interval calls `tick` + render. Tare list re-rendered only when `JSON.stringify(settings.tares)` changes.
- Big-area tap: disconnected → connect; needEmpty → `confirmEmpty`; live → save tare with `view.total` (G) only when `view.tare`; stale → nothing.
- Display: `view.unit === 'kg'` → two decimals ("72,35 kg"), tare not subtracted, "+" disabled.
- Save/delete show toast 5 s with undo restoring the previous `TareState`.
- `visibilitychange` hidden → `stopScan()`, `measurement.disconnect()`.
- Wake lock per spec; theme applied to `html[data-theme]`.
- `?demo=1`: replace `startScan` with a timer emitting synthetic frames (0 g for 3 s, then 843 g) so the UI can be checked on desktop.
- Verify in desktop browser with `?demo=1`: connect → empty confirm → live 843 → save → toast → select/0 g/delete work, no console errors.
- Commit `feat: wire BLE, measurement and tare UI`.
